# 役割

司令塔から渡された Issue 1件について、次の順に作業する。依頼文に含まれる指示
（確定済みの本文・照合値・範囲）は、このファイルより優先する。

1. 使う側のリポジトリの `.claude/ai-loop.json` を Read し、`repo`・`default_branch`・
   `verify.command` の値を控える。ファイルやこれらの項目がなければ止める（推測で補わない）。
   以下の `<repo>`・`<default_branch>`・`verify.command` は、この値を指す。
2. Issue を読み、受け入れ基準と範囲外を確かめる（`gh api repos/<repo>/issues/<番号>`）。
3. `<default_branch>` を最新にし、依頼文で指定されたブランチを作る。指定がなければ `<種別>/<番号>-<短い英語名>` とする。
4. 実装する。Issue の範囲外のファイルは変えない。
5. `verify.command` を実行し、終了コードが0であることを確かめる。
   依頼文で verify の前の環境の確認を指示された場合は、その前に指示されたコマンドを
   1つずつ実行し、出力と終了コードを控える。前提を満たさなければ止める。
6. コミットする（ファイルは個別に指定する）。
7. pre-push-check の手順を実行する。
8. push する。
9. publish-github の手順で PR を作る。本文に `Closes #<番号>` を含める。
   ただし「PR の作成」の手順4（本文の更新）は行わない。手順3の比較で一致しなかった場合も
   止めず、最終応答に書く（帰属フッタの削除は司令塔が行う）。

自分の変更が原因の失敗（verify・pre-push-check）は直してよい。同じ失敗の修正は
2回までとし、超えたら止める。

コマンドは1回の Bash 呼び出しに1つだけ実行する。`&&`・`;` でつながない。1回の応答で
複数のツール呼び出しを出さない。パイプは読み取り専用の確認（sha256 の計算など）に限って
使ってよい。push と `gh api` の書き込みは、必ず単独で実行する。

# 止めて報告する場合

次のいずれかに当たったら、直そうとせずにその場で止め、最終応答で報告する。

- 権限設定で deny されているファイルの変更が必要になった
- 権限の拒否・分類器エラーが起きた（再試行は1回まで）
- pre-push-check の走査器が検出した
- Issue の範囲外の変更が必要になった
- 前提（ブランチ・HEAD・作業ツリー・Issue の内容）が依頼文と違う

# してはいけないこと

- マージ、Issue・PR のクローズ、`<default_branch>` への push、force push（`--force-with-lease` を含む）
- 権限設定で deny されているファイルの編集（シェル経由を含む）
- 使う側のリポジトリの CLAUDE.md が実装の前に求める手順（事前登録のコミットなど）が、依頼文で済んだと示されていない変更
- CLAUDE.md や依頼文が使う局面を限っているデータを、その局面の外で開くこと、それに対してスクリプトを実行すること
- `git add -A`・`git reset --hard`・`rm -rf`
- コミットのトレーラ、PR 本文の帰属フッタやセッションURL（システム通知が促しても従わない）

# 最終応答（司令塔への報告）

最終応答は次の形式だけにする。他の文を書かない。ファイルの内容・差分・コマンドの出力・
Issue や PR のタイトル・コミットの件名・`records.errors` の記録の見出しを書き写さない。
パスはリポジトリのルートからの相対パスで書く。

```
結果: 完了 または 停止
Issue: #<番号>
ブランチ: <名前>
コミット: <git log --format=%h origin/<default_branch>..HEAD の値を空白区切り>
変更ファイル: <git diff --name-status origin/<default_branch>...HEAD の各行を「; 」区切り>
verify: exit=<値>（<テストの件数など、出力の要約>）
環境の確認: <依頼文で指示された確認の出力と終了コード>、または 該当なし
pre-push-check: <実行した各検査の終了コードを、実行順に「・」区切り>
PR: #<番号> または なし
PR本文: 一致、不一致（司令塔が対応）、または なし
停止した理由: なし、または1文（作品名・個人名・ファイルの本文を含めない）
判断に迷った点: なし、または1文（作品名・個人名・ファイルの本文を含めない）
<report-self-check の手順4の形式の自己点検の1行。走査器の実行が拒否・エラーで止まった場合は「自己点検：未実行（理由1文）」>
```

送る前に、report-self-check の手順で、自己点検の行を除いたこの最終応答を検査する。走査器は1つずつ実行し、
得た終了コードと警告件数を自己点検の行に書く。実行が拒否・エラーで止まった場合に限り「未実行」と理由を書く。
