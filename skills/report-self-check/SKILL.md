# 報告前の自己点検

報告本文には，個人情報や，リポジトリごとに書いてはいけない名前が紛れ込み
やすい．このスキルは，報告を送る**直前**に，下書きを機械的に
検査する．

## 設定

最初に `.claude/ai-loop.json` を Read する．ファイルがない，または `scanners` がない
場合は，ここで止めて報告する（走査器を推測で補わない）．
同じ会話ですでに Read していて，その後このファイルを変えていない場合は，読み直さなくてよい（Read ツールが「変化なし」と返した場合も読んだものとみなす）．

## 手順1: 下書きをファイルに書き出す

報告の下書き全文を `/tmp/selfcheck_draft_<役割>.md` に書き出す．`<役割>` は，
司令塔（commander スキル）なら `commander`，実装役（implementer エージェント）なら
`implementer`，それ以外なら `main` とする．役割ごとに分けるのは，司令塔と実装役が
同じファイルを上書きし合わないようにするためである．

前回の下書きが残っていても使わず，毎回 Write で全文を書き直す．要約・省略はせず，
実際に送るつもりの本文をそのまま書く．手順4の自己点検の行は下書きに含めない．

## 手順2: 走査器を実行する

リポジトリのルートで，`scanners` の各項目の `command` の末尾に下書きのパスを付けて，
項目の数だけ1つずつ実行する．例（`command` が `check_no_personal_info.py`，役割が
`main` のとき）：

```bash
check_no_personal_info.py /tmp/selfcheck_draft_main.md
```

すべて終了コード0になるまで下書きを直して繰り返す．警告（2〜3文字の一致など）を出す
走査器（comic_checker の `check_title_leak.py` など）が警告を出した行は，その一致が
実在作品名の一部として書かれていないかを確認する（警告だけでは終了コードは0のままなので，
機械的には止まらない．必ず目で見て判断する）．

## 手順3: 機械で検出できない項目のチェックリスト

下書きを読み直し，次のすべてを確認する．1つでも該当すれば直してから
手順2に戻る．

- コミットの Author・committer 行を貼っていない
- 棚卸し表の見出し列の値を貼っていない
- `git diff` の削除行に作品名・個人名が残っていない
- 伏せ字と置き換え前の対応表・凡例を併記していない
- Issue・ADR・測定結果の要約に，書いてはいけない名前を書いていない
- ツールの自動出力（pytest のヘッダ，一時ディレクトリのパス等）を無加工で
  貼っていない
- 「全文書き写す」指示より記載規則を優先した
- 記載規則に該当するかを「該当しないと確認した」と自分で正当化して
  掲載していない

## 手順4: 自己点検の明示

報告の末尾に次の形式で1行だけ付ける．

```
自己点検：<name1> exit X1・<name2> exit X2（警告 Z 件）
```

- `scanners` の要素の順に，`name` と手順2で得た終了コードを「・」でつないで並べる．
  要素が1つなら1つだけ書く（例：`自己点検：走査器 exit 0（警告 0 件）`）．
- Z は手順2で得た警告件数の合計．
- いずれも手順2で実際に得た値を書く．
- 走査器の実行が拒否・エラーで止まった場合に限り，`自己点検：未実行（理由1文）` と書く．

## 書いてはいけないもの

- 検出内容（作品名・行の本文）を報告に書かない
- スクリプトの標準エラー出力を報告に貼らない（貼ってよいのは手順4の1行だけ）
